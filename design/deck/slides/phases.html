Build order

Six steps, each usable on its own

1 · Skeleton

sites, locations, products, users, ledger, API with ids + retry queue

2 · Inbound

receive, put away, move, count; scanner app begins

3 · Outbound

deliveries, single pick, pack, ship, outbound events

4 · Platen

print points, job status, reprint

5 · More work

batch pick + sort, production, transfers

6 · Switches

containers, SSCC, multi-owner, reports

Stop anywhere

Each step leaves something that works. Step 2 alone is a usable stock tracker with scanners.

API first, screens second

Every step starts with the endpoints and events, then the desktop, then the scanner. The screens are thin.

Design file is the spec

35 screens and 7 flow diagrams in the Simple WMS UI canvas. Build to those, change them when the build teaches something.
