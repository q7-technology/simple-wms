Game Mode

Industrial software that doesn't feel like it

Most warehouse systems are rows of grey tables. Simple WMS gives the manager a picture of the whole warehouse, and gives the floor one clear job at a time.

The map is home

Three zones you can read from across the room: Arriving, Stored and Leaving. Live counts, today's goal with a streak, the next order due and what just happened.

Every job slides over the map

Orders, receiving, stock, the task board, reports and settings open as panels on top, like the inventory screen in a game. Close one and you're back at the warehouse.

The scanner says one thing at a time

Go to this shelf. Scan it. Pick six. Ding. Big buttons for gloved hands, badge or PIN sign-in, and a Switch worker button for handing the scanner over mid-shift.

Trucks and forkliftsA truck rolls in when stock arrives and drives off when an order ships.
Beep and dingA soft sound for an arrival and a shipment, with a volume slider.
Day and nightThe map follows the warehouse's own clock, so late shifts look like late shifts.
A daily goalThe app suggests a fair target from the last four weeks. The manager can change it.

Each game touch is a personal setting that switches off in one click, and they respect your device's reduced-motion setting. The numbers underneath never change.

How it fits together

Three surfaces, one backend

If the screen can do it, a partner system can too. The desktop and the scanner are ordinary API clients with no back door to the database.

Desktop = control

Create, watch, approve, configure. Deliveries, receiving, production, transfers, stock, locations, products, a live task board and an integrations page that shows every event waiting to send.

Scanner = execution

Pick, pack, receive, put away, move, count, look up. Each screen says what it expects, so scanning a shelf when it wanted a product gives a friendly message, not a wrong entry.

API = the only door

Deliveries, receipts, production orders, replenishments, moves, transfers and packs go in. Signed events come out. Same message twice does nothing extra.

Features

Fun on the surface, strict underneath

Small on purpose. Every feature below ends in a ledger line, and every ledger line can become an event.

Append-only stock ledger

Every change is a new line: who, what, how many, from, to, batch, owner, device, when. Nothing is overwritten. Cancel, never delete.

Scanner PWA

Installs from the browser on Zebra and Honeywell Android scanners. Big targets, badge or PIN sign-in, keeps the current task through Wi-Fi drops.

Everything is a task

Receive, put away, pick, pack, ship, move, count, replenish, transfer. One engine, one screen pattern, one audit trail.

Production in and out

Pick components to the line, then scan the production order to put finished goods away. Batch read straight from the order QR.

One API, one event envelope

Standard bodies in. One signed, queued, retried event shape out. The ERP, a carrier and a print service are all just subscribers.

Multi-warehouse from day one

Transfers between sites with an in-transit bucket, so stock is never lost and never counted twice.

Prints nothing itself

Sends a template name plus JSON to Platen or any print service. Redesign a label without touching the WMS.

Three kinds of key

Microsoft or other single sign-on, or a password, on the desktop. Badge or PIN on the floor. Scoped API keys for systems. Supervisor badge for risky actions.

Integration

One shape in, one envelope out

Every inbound body carries a message_id, an external_ref, a warehouse and an owner. Every outbound event is HMAC-signed, queued per subscriber and retried with backoff until the listener answers.

  • Endpoints: deliveries, receipts, production orders, replenishments, moves, transfers, pack, stock lookup, location suggest, scan parse
  • Events: receipt.confirmed, stock.moved, stock.adjusted, delivery.allocated / picked / packed / shipped, transfer.shipped / received, production.components_issued / received
  • Scan parser handles GS1 (QR, DataMatrix, GS1-128, Digital Link), JSON in a QR, custom per-site patterns and plain text
  • Printing: template name + JSON to Platen or your own print service, on the same retry queue
  • CSV import with a preview that names the problem rows before anything commits

Stack

Boring on purpose

The fun lives in the screens. The backend is the dullest, most dependable thing we could build: a handful of containers, one database, no message broker.

API · Python 3.12 + FastAPI

Typed with Pydantic, OpenAPI for free. Python so pyrfc is there if an SAP bridge is ever needed. SQLAlchemy 2, Alembic migrations.

PostgreSQL 16

Ledger as an append-only table with a trigger that blocks UPDATE and DELETE. Events and print jobs in a durable queue table, drained by a Python worker.

Vite + React + Tailwind

Desktop app and scanner PWA from one repo, two entry points. The map is plain SVG, the sounds are made in the browser, and the scanner's service worker caches the shell so it opens offline.

Get started

From clone to warehouse map

Copy the env file and set two secrets, build the two apps, bring it up, and make your first admin. Then register a scanner on the Users screen and install the PWA from its browser.

View on GitHub Report an issue
Terminal 
git clone https://github.com/q7-technology/simple-wms
cd simple-wms
cp .env.example .env     # set POSTGRES_PASSWORD and WMS_SECRET_KEY
(cd apps/desktop && npm install && npm run build)
(cd apps/scanner && npm install && npm run build)
docker compose up -d
docker compose exec api wms create-user --username you --role admin

# desktop  → https://<WMS_DOMAIN>/
# scanner  → https://<WMS_DOMAIN>/scan/
# api docs → https://<WMS_DOMAIN>/docs
